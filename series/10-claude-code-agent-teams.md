# Claude Code Agent Teams 完整指南

> 多智能体协作实战手册

---

## 概述

Agent Teams 是 Claude Code 的实验性功能，用于协调多个 Claude 实例在同一个项目中协同工作。与单智能体串行模式不同，它引入了真正的协作机制：多个 AI 可以并行工作、互相通信、共享任务进度，甚至通过「对抗式讨论」验证判断。

---

## 核心组件

### Team Lead（团队负责人）

团队的主会话，负责：
- 生成队友
- 分配任务
- 协调工作
- 汇总结果

可设置为仅负责协调（不直接写代码）。

### Teammates（队友智能体）

各自独立执行任务的智能体：
- 有独立的上下文窗口
- 加载项目相关信息（CLAUDE.md、MCP 服务、技能）
- 可以直接与其他队友通信

### Task List（共享任务列表）

- 三种状态：pending、in progress、completed
- 支持任务依赖，未解决依赖的任务无法被认领
- 使用文件锁机制防止竞争

### Mailbox（消息系统）

- `message`：向指定队友发送消息
- `broadcast`：向所有队友广播（成本随规模增长）

---

## Agent Teams vs Subagents

| 特性 | Subagents | Agent Teams |
|------|-----------|-------------|
| 上下文 | 独立窗口，结果返回主智能体 | 独立窗口，完全自主 |
| 通信 | 仅向主智能体汇报 | 队友之间直接通信 |
| 协调 | 主智能体统一管理 | 共享任务列表，自主协调 |
| 适用场景 | 专注任务，只需结果 | 复杂任务，需要讨论协作 |
| Token 成本 | 较低 | 较高 |

**选型建议**：
- 快速明确产出 → Subagents
- 复杂需协作 → Agent Teams

## 快速设置指南

### 步骤 1：启用实验性标志

```bash
nano ~/.claude/settings.json
```

添加配置：

```json
{
  "env": {
    "CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": "1"
  }
}
```

### 步骤 2：选择显示模式

| 模式 | 说明 |
|------|------|
| in-process | 所有队友运行在同一终端，用 Shift+Up/Down 切换 |
| tmux | 分屏模式，每个队友独立窗格，需要 tmux |

默认 auto：检测到 tmux 时自动使用分屏模式。

```json
{
  "teammateMode": "in-process"
}
```

或启动时覆盖：

```bash
claude --teammate-mode in-process
claude --teammate-mode tmux
```

### 步骤 3：安装 tmux（如需分屏）

```bash
# Mac
brew install tmux

# Ubuntu/Debian/WSL
sudo apt update && sudo apt install tmux
```

### 步骤 4：验证启用

重启 Claude Code，运行 `/config` 查看配置列表。

## 创建团队

### 简单方式

```
创建一个智能体团队来重构认证模块。
将工作分解为可以独立完成的并行任务。
```

### 手动指定

```
创建一个包含 3 个队友的团队：
- 一个重构登录流程
- 一个重构注册流程
- 一个为两者更新测试

每个队友使用 Sonnet 模型。
```

## 导航与交互

### In-Process 模式

| 操作 | 快捷键 |
|------|--------|
| 切换队友 | Shift+Up / Shift+Down |
| 进入队友视图 | Enter |
| 回到 Lead | Escape |
| 打断队友 | Escape |
| 显示任务列表 | Ctrl+T |

### Split-Pane 模式

- 点击窗格选择队友
- 在对应分屏中输入指令
- 执行 /tasks 查看任务列表

## 高级控制

### 委托模式

Team Lead 只负责指挥，不改代码：

1. 启动团队
2. 按 Shift+Tab 切换

### 计划批准

队友动手前先提交规划：

```
创建一个架构师队友来重构数据库架构。
在它们进行任何更改之前要求计划批准。
```

Team Lead 可批准或拒绝并反馈。

### 指定智能体模型

```
创建一个包含 4 个队友的团队：
- 一个使用 Haiku 的研究员，用于快速查找信息
- 一个使用 Opus 的架构师，用于复杂设计决策
- 两个使用 Sonnet 的实现者，用于实际代码更改
```

### 预批准权限

```
/permissions
```

提前批准常用操作，避免频繁请求。

### 关闭队友

```
请关闭队友 researcher
```

### 清理团队

```
清理团队
```

（需先关闭所有队友）

## 实战应用场景

### 场景 1：并行代码审查

```
创建一个智能体团队来审查 PR #142，生成三个审查员：
- 安全专家：检查漏洞、注入风险、认证缺陷
- 性能分析师：查找瓶颈、N+1 查询、内存问题
- 测试验证者：检查边缘情况和测试覆盖率
```

### 场景 2：对抗式调试

```
用户报告结账端点间歇性 500 错误，大约 5% 的请求失败。

创建 5 个队友调查不同可能原因：
1. 数据库连接池在高负载下耗尽
2. 库存预留中的竞态条件
3. 第三方支付 API 超时处理
4. 内存压力导致垃圾回收暂停
5. 服务间网络问题

让队友相互挑战、反驳彼此的理论。
```

### 场景 3：跨层功能开发

```
创建一个智能体团队来开发通知系统：
- 队友 1：后端 API
- 队友 2：数据库表结构和迁移
- 队友 3：前端 React 组件
- 队友 4：实时更新的 WebSocket 集成
- 队友 5：端到端集成测试
```

## 最佳实践

### 适合场景

- 并行推进能明显提高效率
- 各个队友可在相对独立范围工作
- 调研、代码审查、新功能拆分开发
- 需要队友之间直接讨论、对齐结论

### 不适合场景

- 任务本身是严格顺序的，无法并行
- 多个队友需要频繁修改同一个文件
- 工作之间强依赖，容易相互等待
- 体量很小的日常任务，协调成本高于收益

### 注意事项

1. **Token 成本**：每个队友是独立实例，成本随数量线性增长
2. **任务粒度**：过小协调成本高，过大返工风险高
3. **文件隔离**：避免多人修改同一文件
4. **持续关注**：定期查看进度，及时调整策略

### 当前限制

- 不支持会话恢复
- 任务状态可能不同步
- 单会话单团队
- 不支持嵌套团队

---

## 总结

Agent Teams 是当前自然语言多智能体编排中较为优雅的实现。它与 Claude Code 生态深度结合，引入了声明式的团队协作机制。适用于复杂多模块开发、多角度调研或需要并行推进的场景。
