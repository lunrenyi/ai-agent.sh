## 什么是 AI Agent

### 从一个比喻开始

想象一下：

- **LLM（大语言模型）**就像一个 **博学但足不出户的专家**
  - 它读过海量的书，知道很多知识
  - 但它只能在你问它的时候回答问题
  - 它不能自己出去办事，不能查资料，不能操作电脑

- **AI Agent** 就像一个 **全能助理**
  - 这个助理不仅有那个专家的大脑
  - 还能跑腿、查资料、操作电脑
  - 你给它一个目标，它就能自己想办法完成

```
┌─────────────────────────────────────────────────────────┐
│                    传统 LLM                             │
│  用户 ──────► [专家大脑] ──────► 文本回答               │
│                    ❌ 不能办事                           │
└─────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────┐
│                     AI Agent                            │
│  用户 ──────► [专家大脑] ──────► [工具] ──────► 结果    │
│                    ↳ 规划、记忆、决策                    │
└─────────────────────────────────────────────────────────┘
```

### 核心公式

```
AI Agent = LLM (大脑) + Planning (规划) + Memory (记忆) + Tools (工具)
```

### Agent 和 LLM 的区别

| 特性 | LLM | AI Agent |
|------|-----|----------|
| 能力 | 回答问题 | 完成任务的 |
| 行动 | 只能说话 | 能操作电脑 |
| 记忆 | 有限上下文 | 可长期记忆 |
| 模式 | 你问我答 | 自主规划执行 |

## 一、为什么需要 AI Agent

### LLM 的局限

LLM（大型语言模型）虽然强大，但有三个关键局限：

1. **知识过时** - 训练数据有截止日期，不知道最新信息
2. **无法行动** - 只能输出文本，不能执行操作
3. **记忆有限** - 上下文窗口有限，记不住太多东西

### Agent 如何解决

```
┌─────────────┬────────────────────────────────────┐
│   问题      │              Agent 解决方案          │
├─────────────┼────────────────────────────────────┤
│ 知识过时    │ 接入搜索引擎，随时查最新资料         │
│ 无法行动    │ 调用 API、执行代码、操作文件        │
│ 记忆有限    │ 接入数据库、向量库，长期记忆        │
└─────────────┴────────────────────────────────────┘
```

## 二、从概念到实现：一个最简单的 Agent

### 核心循环

所有 Agent 的核心都是一个 **循环**：

```python
# 伪代码
while True:
    # 1. 把问题交给模型
    response = model.chat(messages)

    # 2. 检查是否需要调用工具
    if response.needs_tool:
        # 3. 执行工具
        result = execute_tool(response.tool_call)
        # 4. 把结果告诉模型，继续思考
        messages.add(result)
    else:
        # 5. 任务完成，返回结果
        return response.text
```

这个循环就是 Agent 的 **"心跳"**。

### 极简实现（来自 learn/V0）

用 Shell 只需要 ~150 行代码就能实现一个 Agent：

```bash
# 核心循环
while true; do
    # 调用 API
    response=$(call_api "$history")

    # 检查是否需要工具调用
    if [[ "$stop_reason" != "tool_use" ]]; then
        echo "$response"
        return
    fi

    # 执行工具调用
    for tc in $tool_calls; do
        output=$(execute_tool "$tc")
        results+=("$output")
    done

    # 更新对话历史，继续循环
    history=$(update_history "$history" "$results")
done
```

## 三、工具系统：Agent 的"四肢"

### 四个基本工具

最基础的 Agent 只需要 **4 个工具**就能完成 90% 的编程任务：

```
┌─────────────┬──────────────────┬─────────────────┐
│ 工具        │ 作用             │ 示例            │
├─────────────┼──────────────────┼─────────────────┤
│ bash        │ 运行命令         │ npm install     │
│ read_file   │ 读取文件        │ 查看代码        │
│ write_file  │ 创建文件        │ 写新文件        │
│ edit_file   │ 修改文件        │ 改 bug         │
└─────────────┴──────────────────┴─────────────────┘
```

### 工具的定义

每个工具需要告诉模型三件事：

```json
{
  "name": "bash",
  "description": "执行 shell 命令，返回命令输出",
  "parameters": {
    "type": "object",
    "properties": {
      "command": {
        "type": "string",
        "description": "要执行的命令"
      }
    },
    "required": ["command"]
  }
}
```

### 工具调用的过程

```
用户: "帮我创建一个 hello.py 文件"

模型思考: 用户想要创建文件，我需要调用 write_file 工具

模型输出:
{
  "tool_call": {
    "name": "write_file",
    "arguments": {
      "path": "hello.py",
      "content": "print('Hello, World!')"
    }
  }
}

系统执行: 实际创建文件

系统返回: "文件已创建"

模型最终输出: "已为你创建 hello.py 文件！"
```

## 四、规划能力：让 Agent 学会思考

### 什么是规划

规划就是 **把大目标拆成小步骤**。

就像你要去旅行：
- **没有规划**: "我想去旅游" → 不知道去哪、怎么去
- **有规划**: "北京→上海→苏州→杭州，飞机去，高铁回" → 清晰可行

### Agent 的规划方式

#### 1. 思维链 (CoT)

让模型**一步一步想**，不要直接给答案。

```
❌ 错误: "用户问 234*567 等于多少"
   模型直接猜一个答案

✅ 正确: "234 * 567 = 234 * 500 + 234 * 67 = 117000 + 15678 = 132678"
```

在 Prompt 中加一句: **"Let's think step by step"**

#### 2. ReAct 模式

这是最常用的 Agent 执行范式：

```
循环:
  思考(Think) → 行动(Act) → 观察(Observe)
```

**一个实际例子**:

```
用户: "帮我查下北京今天天气，如果下雨就带伞"

Loop 1:
  Think: 用户想知道天气，需要先调用天气 API
  Act: 调用天气查询工具
  Observe: 返回"今天晴转多云"

Loop 2:
  Think: 天气是多云，不下雨，不需要带伞
  Act: 返回最终回答
  Observe: 任务完成
```

#### 3. 计划与执行分离

复杂任务分两步：
1. **先规划**: 生成完整的步骤清单
2. **再执行**: 按步骤顺序执行

```
用户: "帮我搭建一个博客网站"

📋 规划阶段:
   1. 创建项目目录
   2. 初始化 Node.js 项目
   3. 安装依赖
   4. 创建首页代码
   5. 启动服务

⚙️ 执行阶段:
   [执行第1步] → [执行第2步] → ... → 完成
```

## 五、记忆系统：让 Agent 记住一切

### 两种记忆

| 记忆类型 | 相当于 | 特点 |
|---------|--------|------|
| **短期记忆** | 人的工作记忆 | 有限，容易忘 |
| **长期记忆** | 人的知识库 | 持久，可检索 |

### 短期记忆：对话历史

```python
# 对话历史就是短期记忆
messages = [
    {"role": "user", "content": "你好"},
    {"role": "assistant", "content": "你好！"},
    {"role": "user", "content": "我刚才说什么了？"},
    # 模型通过历史知道"刚才"说了"你好"
]
```

**问题**: 上下文窗口有限（GPT-4 约 100K tokens）

**解决**: 压缩、摘要、只保留关键信息

### 长期记忆：RAG

RAG = 检索增强生成 (Retrieval-Augmented Generation)

```
用户: "我们公司年假制度是什么？"

     ┌─────────────────────────────────┐
     │  1. 把公司文档存入向量数据库      │
     │  2. 用户提问时，检索相关内容      │
     │  3. 把相关内容给模型作为参考      │
     │  4. 模型生成准确答案              │
     └─────────────────────────────────┘
```

### 经验记忆：从错误中学习

Agent 可以在任务完成后**反思总结**：

```python
# 任务完成后
reflection = model.analyze(
    task="配置活动",
    result="失败 - 计价 Bug",
    cause="未考虑预售定金与店铺券叠加规则"
)

# 存储经验
memory.save(
    category="activity_config",
    pattern="预售+优惠券",
    lesson="必须先检查互斥规则"
)

# 下次遇到类似任务
similar = memory.retrieve("预售+优惠券")
# Agent 会主动先检查互斥规则
```

## 六、提示词工程：与 Agent 对话的艺术

### 什么是提示词

Prompt（提示词）就是 **你发给模型的话**。

Prompt 写得好不好，直接决定 Agent 表现好不好。

### 四个关键技巧

#### 1. 角色设定

```
❌ 模糊: "帮我写个文案"

✅ 明确: "你是一个有 10 年经验的电商文案专家，
         专门写吸引人的商品标题。要求：
         - 30 字以内
         - 包含品牌名和核心卖点
         - 适合年轻人"
```

#### 2. 给示例 (Few-Shot)

```
任务: 判断情绪

❌ 直接问: "这个产品太棒了" 是正面还是负面？

✅ 给示例:
   "太喜欢了" → 正面
   "很差评" → 负面
   "一般般" → 中性
   "这个产品太棒了" → ?
```

#### 3. 指定输出格式

```
❌ 随便输出: "好的，我帮你整理一下..."

✅ 指定格式:
   "用 JSON 格式输出:
    {'情绪': '正面', '关键词': ['棒']}"
```

#### 4. 分步指导

```
❌ 一步到位: "分析这段代码有什么问题"

✅ 分步骤:
   "第一步: 代码实现的是什么功能？
    第二步: 找出其中的 bug
    第三步: 给出修复方案"
```

## 七、Agent 的三种设计范式

### 范式一：最小可用 (最简单)

```
用户 → 意图识别 → RAG → 工具 → 回答
```

**特点**:
- 单轮对话
- 线性流程
- 无状态

**适合场景**: 简单问答、资料查询

### 范式二：工作流式 (最可控)

```
用户 → [节点A] → [节点B] → [节点C] → 回答
            ↓
        分支/条件
```

**特点**:
- 预定义流程
- 确定性执行
- 适合复杂业务

**适合场景**: 客服对话、审批流程

### 范式三：动态规划 (最智能)

```
用户 → 思考 → 行动 → 观察 → 思考 → 行动 → ...
              ↑___________________|
```

**特点**:
- 运行时决策
- 灵活应变
- 可能失控

**适合场景**: 复杂任务、探索性工作

## 九、工程实践中的关键挑战

### 1. 幻觉问题

**问题**: 模型会"编造"不存在的事实

**解决**:
- 用 RAG 接入真实数据
- 要求模型标注不确定的内容
- 增加验证步骤

### 2. 上下文溢出

**问题**: 对话太长，模型"失忆"

**解决**:
- 压缩历史消息
- 定期摘要
- 清理无关内容

### 3. 工具调用错误

**问题**: 调用了不存在的工具、参数错误

**解决**:
- 严格参数校验
- 错误反馈循环
- 详细日志记录

### 4. 无限循环

**问题**: Agent 重复做同一件事

**解决**:
- 设置最大步数
- 检测重复模式
- 超时自动停止

## 十、个人实践总结

来自原文作者的 9 条经验：

1. **从最小可用开始** - 不要一开始就做复杂的 Agent
2. **混合架构更稳** - 工作流 + AI 智能内核
3. **稳定比智能更重要** - 准确率 85% 但可预测 > 95% 但随机
4. **没有银弹** - AI 解决不了业务理解的根本问题
5. **深入理解业务** - 架构师和 Prompt 工程师都需懂业务
6. **知识有壁垒** - 领域知识需要专门维护
7. **评估驱动迭代** - 不能凭感觉，要数据说话
8. **用户体验关键** - 技术强 ≠ 产品好
9. **Agent 是团队成员** - 长期看 Agent 比人更可靠
