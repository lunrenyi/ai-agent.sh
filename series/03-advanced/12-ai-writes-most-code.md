# 当 AI 写了几乎所有代码，软件工程会怎样？

> 原文作者：Gergely Orosz (The Pragmatic Engineer)
> 原文链接：https://www.pragmaticengineer.com/p/ai-writes-most-code
> 写作时间：2026年1月

## 核心观点

AI 编程工具已达到拐点，**AI 写出 90% 代码**不再是预测，而是正在发生的大趋势。软件工程这个职业正在被"重构"。

> "这个职业正在被大规模重构，程序员亲手贡献的代码比例越来越少。" — Andrej Karpathy

## 1. 顿悟时刻：AI 编程能力的飞跃

### 模型拐点：2025年11-12月

| 模型 | 发布者 | 发布时间 |
|------|--------|----------|
| Gemini 3 | Google | 2025年11月17日 |
| Opus 4.5 | Anthropic | 2025年11月24日 |
| GPT-5.2 | OpenAI | 2025年12月11日 |

### 行业声音

**Google 首席工程师 Jaana Dogan**：
> "我们从去年开始就在 Google 尝试构建分布式智能体编排系统。我给 Claude Code 描述了一下这个问题，它一小时内就生成了我们去年才做出来的东西。"

**Vercel CTO Malte Ubl**：
> "有了 Opus 4.5 之后，世界完全不一样了。软件生产的成本正在趋近于零。"

**Ruby on Rails 创始人 DHH**：
> "去年夏天我还说不让 AI 直接写代码，但事后看来，那是因为当时的模型还不够好！现在彻底反过来了。"

**Claude Code 创造者 Boris Cherny**：
> "上个月是我作为工程师第一次完全没有打开 IDE。Opus 4.5 写了大约 200 个 PR，每一行代码都是它写的。"

## 2. 坏消息：专业知识的价值在下降

### 正在贬值的技能

| 技能 | 过去价值 | 未来价值 |
|------|----------|----------|
| 原型开发 | 高 | 低（产品经理也能做） |
| 编程语言多面手 | 高 | 中（AI 都能写） |
| 语言专精 | 高 | 低（跨栈能力更重要 |
| 执行明确工单 | 高 | 低（AI 自动完成） |

### 关键变化

- **原型开发**：Lovable、Replit 等工具让非技术人员也能构建软件
- **语言专精**：一个后端工程师可以通过提示词生成前端、跨平台、甚至原生移动代码
- **Ticket 实现**：Cursor 团队已实现自动化流程，所有 Linear 工单自动传给 Cursor 完成

## 3. 好消息：软件工程师比以前更值钱

### 核心能力变得更重要

| 能力 | 为什么重要 |
|------|------------|
| **技术负责人特质** | 写出能让 AI 正确生成代码的工单 |
| **测试基础设施** | 验证 AI 输出，减少幻觉 |
| **产品思维** | 明确"做什么"比"怎么做"更重要 |
| **架构决策** | 代码生成越快，越需要明确软件结构 |
| **技术债管理** | 追踪和处理更多代码带来的技术债 |
| **系统思维** | 构建可靠、高性能、可扩展、安全的系统 |

### 产品工程师模式

采用"产品工程师"模式的初创公司：
- **WorkOS**：80 个工程师只配 1 个产品经理
- **Linear**：成立头几年完全没有产品经理

> 做扎实软件工程师，而不仅仅是"写代码的"，会比以前更受追捧。

## 4. 残酷的现实：令人不安的后果

### 代码质量下降

- **变更失败率上升 30%**（Cortex 2026 基准报告）
- 审查标准无法跟上代码产出速度
- 薄弱的工程实践会更快暴露问题

### 工作与生活边界

- AI 智能体可在手机/浏览器运行
- 开发者随时随地都能被找到
- "不在电脑前"作为仅存的防线可能不复存在

### 初级工程师的困境

以前对高级工程师的要求，现在变成对入门级工程师的期望：
- 善于将工作拆解为小任务
- 跨栈工作能力
- 产品思维
- 架构决策能力
- 验证 AI 输出
- 自动化测试和可观测性

### 计算机科学教育

- AI 生成申请可能塞满招聘通道
- 大学可能成为"垃圾过滤器"
- CS 教育可能成为入行刚需

## 5. 产品管理 vs 软件工程：融合还是分离？

### 边界更加模糊

- **工程师更有产品思维**：直接与客户交流，主动修复 Bug
- **产品经理更亲力亲为**：自己构建原型，有时自己提交修复

### "中间层软件工作"正在消失

Linear 联合创始人 Karri Saarinen：
> "纯编码智能体工作流现在能够根据目标、上下文和任务直接产出可用代码。它们运行得更加独立，你需要碰代码的时候越来越少。

> **软件设计，从这个意义上说，不是关于工件或工具的。** 它是关于通过创意、探索、调研和讨论来形成并打磨意图的清晰度。

> 在这个时代，指导和管理智能体的工作本身就成了一门手艺。"

## 总结

### 核心洞察

| 维度 | 变化 |
|------|------|
| **代码生成** | 从手工 → AI 主导 |
| **工程师角色** | 从"写代码的" → "系统思考者" |
| **瓶颈** | 从实现 → 评审 |
| **价值** | 从"能写代码" → "能正确使用 AI" |

### 机会与挑战

**好消息**：
- AI 推动大家认真思考验证、可观测性、架构
- 市场对软件专业人才的需求可能更高

**坏消息**：
- 变化非常迅猛
- 失去亲手写代码的成就感

> "我不禁想：从编写复杂代码的艰难中获得的那种成就感，未来还会有吗？是的，AI 很方便，但也有一种失去。"
