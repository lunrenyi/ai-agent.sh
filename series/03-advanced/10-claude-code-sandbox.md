# Claude Code 沙箱隔离完全指南

> 了解 Claude Code 的沙箱化 bash 工具如何提供文件系统和网络隔离，以实现更安全、更自主的代理执行。

## 概述

Claude Code 具有原生沙箱隔离功能，为代理执行提供更安全的环境，同时减少了对持续权限提示的需求。沙箱隔离通过操作系统级别的原语（macOS 的 Seatbelt，Linux 的 bubblewrap）来强制执行文件系统和网络隔离。

## 核心价值

### 为什么沙箱隔离很重要

传统基于权限的安全性问题：
- **批准疲劳**：重复点击"批准"导致注意力下降
- **生产力降低**：持续中断减慢开发流程
- **自主性受限**：等待批准时无法高效工作

沙箱隔离的解决方案：
1. 定义清晰的边界（精确指定可访问的目录和网络主机）
2. 减少权限提示（沙箱内的安全命令自动允许）
3. 维护安全性（访问沙箱外资源会触发即时通知）
4. 启用自主性（在定义限制内更独立运行）

> ⚠️ **警告**：有效的沙箱隔离需要**同时**进行文件系统和网络隔离。配置时需确保不会在系统中创建绕过。

## 工作原理

### 文件系统隔离

- **默认写入行为**：对当前工作目录及其子目录的读写访问
- **默认读取行为**：对整个计算机的读取访问（除被拒绝的目录）
- **被阻止的访问**：无法在没有明确权限的情况下修改当前工作目录外的文件
- **可配置**：通过 `sandbox.filesystem.allowWrite` 向其他路径授予写入访问权限

### 网络隔离

通过在沙箱外运行的代理服务器控制：
- 域名限制（只能访问批准的域名）
- 用户确认（新的域名请求会触发权限提示）
- 自定义代理支持
- 全面覆盖（适用于所有脚本、程序和子进程）

### 操作系统级别的强制执行

- **macOS**：使用 Seatbelt
- **Linux / WSL2**：使用 bubblewrap
- **不支持 WSL1**（需要 WSL2 的内核功能）

## 入门

### 前置条件

- **macOS**：开箱即用
- **Linux / WSL2**：安装 `bubblewrap` 和 `socat`

```bash
# Ubuntu/Debian
sudo apt-get install bubblewrap socat

# Fedora
sudo dnf install bubblewrap socat
```

### 启用沙箱隔离

运行 `/sandbox` 命令打开菜单选择沙箱模式。

### 两种沙箱模式

| 模式 | 说明 |
|------|------|
| 自动允许模式 | 沙箱内命令自动运行，无法沙箱化的命令回退到常规权限流程 |
| 常规权限模式 | 所有命令都通过标准权限流程 |

> ℹ️ **说明**：自动允许模式独立于权限模式设置工作。即使不在"接受编辑"模式中，沙箱化 bash 命令也会自动运行。

## 配置沙箱隔离

### 向特定路径授予子进程写入访问权限

```json
{
  "sandbox": {
    "enabled": true,
    "filesystem": {
      "allowWrite": ["~/.kube", "//tmp/build"]
    }
  }
}
```

路径前缀含义：
| 前缀 | 含义 | 示例 |
|------|------|------|
| `//` | 从文件系统根目录的绝对路径 | `//tmp/build` → `/tmp/build` |
| `~/` | 相对于主目录 | `~/.kube` → `$HOME/.kube` |
| `/` | 相对于设置文件的目录 | `/build` → `$SETTINGS_DIR/build` |
| `./` 或无前缀 | 相对路径 | `./output` |

> 💡 **注意**：当在多个 settings scopes 中定义 `allowWrite` 时，数组被**合并**。

### 安全限制

- **网络过滤**：不检查通过代理的流量，用户需确保只允许受信任的域
- **域名前置风险**：可能通过域名前置绕过网络过滤
- **Unix Sockets 权限提升**：`allowUnixSockets` 可能授予强大系统服务访问权限
- **文件系统权限提升**：允许写入 `$PATH` 中的可执行文件目录可能导致权限提升

### 沙箱隔离与权限的关系

| 安全层 | 作用 |
|--------|------|
| **权限** | 控制可以使用哪些工具，在工具运行前评估 |
| **沙箱隔离** | 操作系统级别强制执行，限制 Bash 命令的文件系统和网络访问 |

## 安全优势

### 防止提示注入

**文件系统保护：**
- 无法修改关键配置文件（如 `~/.bashrc`）
- 无法修改 `/bin/` 中的系统级文件
- 无法读取被拒绝的文件

**网络保护：**
- 无法向攻击者控制的服务器泄露数据
- 无法从未授权的域下载恶意脚本
- 无法向未批准的服务进行 API 调用
- 无法联系任何未明确允许的域

### 减少攻击面

沙箱隔离限制了以下可能造成的损害：
- 恶意依赖项（NPM 包等）
- 被破坏的脚本
- 社会工程
- 提示注入

## 最佳实践

1. **从限制性开始**：从最小权限开始，根据需要扩展
2. **监控日志**：查看沙箱违规尝试
3. **环境特定配置**：开发和生产环境使用不同规则
4. **与权限结合**：与 IAM 策略一起使用
5. **测试配置**：验证不会阻止合法工作流程

## 限制

- **性能开销**：最小，但某些操作可能稍微较慢
- **兼容性**：某些工具可能需要配置调整或在沙箱外运行
- **平台支持**：macOS、Linux、WSL2（不支持 WSL1 和原生 Windows）
