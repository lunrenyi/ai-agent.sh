# Claude Code 四大扩展模式：从小白到高级用户的进阶指南

> 深入理解 Claude Code 的扩展机制，选择最适合你的协作方式

## TL;DR（太长不看版）

| 模式 | 一句话解释 | 适合场景 |
|------|-----------|----------|
| **Subcommand** | 把常用的话写成快捷短语 | 快速调用固定格式的提问 |
| **Skill** | 给 Claude 添加专业技能 | 长期重复的专业任务 |
| **sub-agents** | 派多个帮手同时干活 | 需要并行处理的批量任务 |
| **Agent Teams** | 组建一个团队分工合作 | 复杂项目需要多人协作 |

---

## 一、先理解基本概念

在深入了解之前，我们需要先明白一个前提：

> **Claude Code 默认只有一个"你"在和它对话。**

这四种扩展模式，本质上都是**让 Claude Code 变得更强大**的方式，区别在于"变强大的方式"不同。

---

## 二、Subcommand：快捷短语

### 什么是 Subcommand？

想象一下：你经常需要让 Claude 帮你审查代码，每次都要输入一大段相同的话，是不是很麻烦？

**Subcommand 就是来解决这个问题的。** 它可以把常用的提问方式，变成一个简短的斜杠命令。

### 举几个例子

**创建之前，你可能需要输入：**
```
请帮我审查当前代码，找出以下问题：1. 代码风格不一致的地方 2. 潜在的性能问题 3. 可能导致 bug 的代码模式
```

**创建 Subcommand 后，只需要输入：**
```
/review
```

### 如何创建？

```bash
# 1. 创建存放命令的文件夹
mkdir -p .claude/commands

# 2. 创建一个 markdown 文件
# 文件名就是命令名，比如 review.md
touch .claude/commands/review.md
```

然后在文件里写上你的 prompt：

```markdown
---
description: 审查代码质量问题
---

请审查当前代码，找出以下问题：
1. 代码风格不一致的地方
2. 潜在的性能问题
3. 可能导致 bug 的代码模式
```

下次直接输入 `/review` 就能用了！

### 适合谁用？

- 经常需要重复某种固定格式的提问
- 不想每次都打长长的一大段话
- 只需要简单功能，不需要自定义工具

---

## 三、Skill：专业技能

### 什么是 Skill？

如果说 Subcommand 是**快捷短语**，那 Skill 就是**专业技能**。

**简单理解：**
- Subcommand = 把一句话简化
- Skill = 给 Claude 添加一项新能力

Skill 比 Subcommand 强大的地方在于：**它可以自带工具**。

### 举几个例子

比如你创建了一个 `sql-optimization` Skill：

```markdown
# SKILL.md
---
name: sql-optimization
description: SQL 查询优化专家
trigger: "sql 优化" OR "优化查询"
---

你是一位 SQL 优化专家。请分析用户提供的 SQL 查询...
```

创建了这个 Skill 后，你只需要说：
```
帮我优化这段 SQL
```

Claude 就会自动加载这个技能，而且它可能还自带工具，比如：
- 连接数据库分析查询计划
- 建议添加索引
- 生成优化后的 SQL

### Subcommand vs Skill

| 对比 | Subcommand | Skill |
|------|------------|-------|
| 能否自定义工具 | ❌ 不能 | ✅ 可以 |
| 能否自动触发 | ❌ 只能手动调用 | ✅ 可以根据描述自动触发 |
| 复杂度 | 简单 | 可以很复杂 |
| 学习成本 | 低 | 稍高 |

### 适合谁用？

- 有复杂的、重复性的专业任务
- 需要自定义工具来自动化操作
- 想让 Claude 在某个领域特别擅长

---

## 四、sub-agents：多个帮手

### 什么是 sub-agents？

想象一下：你要分析 10 个日志文件，一个一个来太慢了。

**sub-agents 就是让你同时派多个"帮手"去干活。**

每个 sub-agent 都是一个独立的 Claude 实例，它们：
- **同时工作** — 10 个文件一起分析
- **互不干扰** — 每个都有自己的独立上下文
- **结果汇总** — 干完活后把结果给你

### 怎么用？

```
sub-agents 5 "分析这 5 个日志文件，找出错误模式"
```

这就相当于派了 5 个助手同时帮你干活！

### 适合谁用？

- 需要同时处理多个相似任务
- 任务之间互不依赖，可以并行
- 需要多个独立视角同时工作
- 大规模数据处理

---

## 五、Agent Teams：团队协作

### 什么是 Agent Teams？

如果说 sub-agents 是**多个帮手**，那 Agent Teams 就是**一个团队**。

团队和帮手的区别是什么？
- **帮手**：各自干完就完事
- **团队**：有分工、有协作、有讨论

### Agent Teams 的组成

| 角色 | 说明 |
|------|------|
| **Team Lead（队长）** | 你是队长，负责分配任务给队员 |
| **Teammates（队员）** | 独立的 AI 帮你干活 |
| **Task List（任务清单）** | 大家共享的任务列表 |
| **Mailbox（消息系统）** | 队员之间可以互相发消息 |

### 怎么用？

首先需要启用（实验性功能）：

```json
// ~/.claude/settings.json
{
  "env": {
    "CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": "1"
  }
}
```

然后直接告诉队长：

```
创建一个智能体团队来重构认证模块
- 一个负责登录流程
- 一个负责注册流程
- 一个负责更新测试
```

### 适合谁用？

| 适合 | 不适合 |
|------|--------|
| 并行代码审查 | 简单的一个小任务 |
| 跨层功能开发（前端+后端+测试） | 强依赖顺序的任务 |
| 需要讨论协作的复杂任务 | 只需要 5 分钟能完成的事 |

## 六、到底该用哪个？

### 选择困难症？记住这个顺序

```
任务越简单 → 用越简单的工具
```

**1. 只想简化提问方式？用 Subcommand**
- 你的痛点：每次要打同样的话
- 解决方案：创建快捷命令

**2. 需要更强大的能力？用 Skill**
- 你的痛点：某个领域需要专业化
- 解决方案：创建带工具的技能

**3. 需要同时干多个活？用 sub-agents**
- 你的痛点：任务太多，一个一个来太慢
- 解决方案：同时派多个帮手

**4. 需要多人分工协作？用 Agent Teams**
- 你的痛点：任务太复杂，需要讨论和分工
- 解决方案：组建团队

### 一句话总结

> **Subcommand 封装提问，Skill 定义能力，sub-agents 找人帮忙，Agent Teams 组建团队。**

## 七、初学者建议

### 从简单开始

作为初学者，我建议按这个顺序学习：

1. **先试试 Subcommand** — 最简单，5 分钟就能上手
2. **再创建几个 Skill** — 体验带工具的专业能力
3. **偶尔用用 sub-agents** — 处理批量任务时很方便
4. **最后尝试 Agent Teams** — 复杂项目再用

## 附录：专业用户对比表

| 特性 | Subcommand | Skill | sub-agents | Agent Teams |
|------|------------|-------|------------|-------------|
| **创建位置** | `.claude/commands/` | `.claude/skills/` | 内置命令 | 实验性功能 |
| **触发方式** | `/command` | `/skill-name` 或描述触发 | `sub-agents N "任务"` | 直接告诉 Team Lead |
| **执行上下文** | 共享主会话 | 共享主会话 | 独立隔离 | 多代理协作 |
| **并行能力** | ❌ | ❌ | ✅ | ✅ |
| **自定义工具** | ❌ | ✅ 可选 | ❌ 使用主会话工具 | ✅ |
| **持久性** | 一次定义，长期使用 | 一次定义，长期使用 | 临时创建 | 项目级 |
| **资源开销** | 零额外开销 | 零额外开销 | 每个子代理独立消耗 | 最高 |
| **适用复杂度** | 低 | 中-高 | 中 | 高 |
| **团队协作** | ❌ | ❌ | ❌ | ✅ |

### 核心区别速记

- **Subcommand** = 快捷 prompt 模板
- **Skill** = 可带工具的专业技能
- **sub-agents** = 临时创建的独立执行者
- **Agent Teams** = 有分工协作的智能体团队

---

## 总结

Claude Code 提供了四层扩展能力：

1. **Subcommand** — 最简单，把常用提问变成快捷命令
2. **Skill** — 更强大，可以添加自定义工具
3. **sub-agents** — 并行处理，同时干多个活
4. **Agent Teams** — 团队协作，分工配合

**记住：从简单开始，用起来再说。** 用熟练了再尝试更高级的模式。
