# Claude Code 创始人访谈：编程正在被"解决"

> Boris Cherny 在 Y Combinator 圆桌访谈中的核心洞察

## 核心观点

### 编程正在被"解决"

Boris Cherny 认为编程正在被 AI 解决。在 Anthropic，很多人已经 70%-100% 用 Claude 写代码，IDE 的存在感正在下降。写代码这件事正从"核心能力"变成"默认能力"。

> "在 Anthropic，我们一直有一个核心理念：我们不是为'今天的模型'做产品，而是为'六个月后的模型'做产品。"

### 产品开发理念

- **不要为今天的模型构建，要为六个月后的模型构建**
- **不要和模型对赌** — 加脚手架也许能多拿 10% 效果，但下一代模型可能直接"白送"
- **功能不是规划出来的，是从用户行为里"长"出来的** — plan mode、CLAUDE.md、co-work 都源于用户已经在做的事

### Claude Code 的诞生

Claude Code 最初只是一个很小的终端程序，用来调用 API 本质上就是个小聊天应用。Boris 当时想"要做编程产品，我得先学会怎么用 API"，于是开始随便 hack。

> "终端这个形态在内部开始火起来之后——其实我做出第一个原型两天后，就把它给团队 dogfooding 了。因为 当你有一个看起来可能有用的点子时，第一反应就是赶紧给别人用，看看他们会怎么用。"

### 终端成为终点的意外

最让 Boris 意外的，是终端居然从"起点"变成了"终点"。他们一开始选择 CLI 只是因为成本最低，没想到它就这样自然地停留在那个形态里，并且跑了起来。

### CLAUDE.md 的哲学

Boris 自己的 CLAUDE.md 只有两行：
1. 每次提 PR 都开启 automerge，只要有人 approve 就自动合并
2. 每次提 PR 都发到内部 stamps 频道，让人来 stamp 一下

> "如果 CLAUDE.md 变得很长，我的建议是：直接删掉，重新开始。模型能力每次都会变，所以更好的方式是用最少的指令把模型拉回正轨。"

### 代码的保质期

Claude Code 被反复重写，六个月前的代码几乎全部消失。重构不是例外，而是常态。

> "六个月前存在的代码，现在几乎没有任何一部分还保留着——它一直在被重写。"

### Agent 能力边界的快速迭代

Agent 的能力边界会每几个月重写一次。你对"它能不能做"的判断很快会过时，工程师必须不断重置认知。

### Plan mode 的未来

Plan mode 未来可能自动进入，再往后可能会消失。其本质只是在 prompt 里加一句"先别写代码"，最终可能一发 prompt 就能完成。

### 多 Agent 协作

并行 sub-agent 本质上是 test-time compute 和上下文隔离的组合，会显著提升复杂任务能力。

### 招聘新趋势

Garry Tan 提到他们现在会根据候选人和 Claude Code 协作的 transcript 来决定是否录用。通过这份记录，几乎能看清一个人的思考方式。

### 1000x 工程师

自从 Claude Code 推出后，Anthropic 的人均工程产出整体涨了 150%。

> "以前在 Meta 负责代码质量，当时我们做'提升生产力'，看到 2% 的提升，都可能需要几百人干一年。所以这种 100% 级别的提升，是完全没见过的，闻所未闻。"

### 对开发者的建议

1. **保持新手心态 (Beginner Mindset)** — 能承认自己错、能丢掉旧经验、能从第一性原理重新思考，比资历更重要
2. **迭代速度本身就是护城河** — Claude Code 可以一天做 20 个原型，快速试错比"设计完美方案"更重要
3. **为模型构建产品** — 观察模型想用什么工具，然后让它更容易做到
