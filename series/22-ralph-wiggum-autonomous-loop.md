# Ralph Wiggum：AI 自主循环编程范式

> 以《辛普森一家》角色命名的 AI 无人值守循环技术，从社区 hack 到官方插件的演进史

## 概述

Ralph Wiggum（简称 Ralph）是由澳大利亚开发者 Geoffrey Huntley 于 2025 年提出的 AI 自主编程循环范式。其核心思想简洁而强大：通过无限循环让 AI 代理自主完成代码编写、测试、修复直到满足验收标准的完整闭环。

## 命名由来

Ralph Wiggum 来自《辛普森一家》中的同名角色——一个永远充满热情但经常犯错的小男孩。这个命名完美诠释了该技术的核心理念：**在不确定的世界中通过确定性的"笨拙"实现最终一致性**。

## 技术原理

### 基础形式

```bash
while :; do cat PROMPT.md | claude-code ; done
```

### 核心机制

1. **每次迭代从干净的上下文开始** - 不依赖上下文窗口的记忆
2. **进展保存在文件和 git 历史中** - 状态持久化而非内存中
3. **使用"反向压力"筛选输出** - 通过测试、lint 等工具产生来筛选有效输出

### Ralph Loop 工作流

```
输入: 带验收标准的任务清单（必须可机器验证通过/失败）

循环:
  1. 选择任务
  2. 生成代码
  3. 运行测试
  4. 测试通过 → 提交 Git + 标记完成
  5. 测试失败 → 抓取日志 → 自动修复 → 重试

直到: 任务完成 或 达到最大迭代次数
```

## 核心理念

### 迭代 > 完美

不要追求一次成功，让循环迭代完善工作。每一次失败都是数据，累积起来就能达到目标。

### 失败是数据

确定性的失败意味着失败是可预测的。当你知道"这样做会失败"时，你就能从中学习并调整策略。

### 无人值守

整个循环可以夜间批量执行，不需要人类持续干预。AI 变成了真正的"执行者"而非"对话者"。

## 解决的问题

**传统模式痛点**：
- Claude 做一轮就说"任务完成"，需要人类反复催促
- 人类需要持续在环监督，效率低下
- 上下文窗口有限制，无法处理长任务

**Ralph 解决方案**：
- 原子化任务拆解 + 本地文件记忆 + 安全护栏
- 任务清单 + 代码生成 + 自动化测试 + 错误修复 + 版本提交的无限循环
- 可离线/夜间运行，真正的无人值守

## 实际应用

- **夜间批量执行任务** - 睡前启动，早上看结果
- **复杂功能开发** - 将大任务拆解为可验证的子任务
- **持续集成** - 作为 CI/CD 流程的一部分
